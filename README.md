# Airline On-Time Semantic Layer

![Airline On-Time Analytics Semantic Layer — business case and AWS technical architecture](docs/Airline%20On-Time%20Analytics%20Semantic%20Layer.png)

*Executive overview: business challenges, governed GraphQL metrics, AWS AppSync, DynamoDB, Lambda, S3, and business value. Demo uses synthetic flight data.*

A small, realistic demo of **AWS AppSync as a semantic layer**. Consumers ask a
business question — *"How reliable is this route, given my definition of on time?"* —
in one GraphQL query, without knowing which store answers which part.

```
                       ┌──────────────────────────── AppSync (GraphQL) ───────────────────────────┐
  client query  ─────▶ │  Query.route / Query.routes      Route.performance(month, thresholdMinutes)│
                       └───────────────┬───────────────────────────────┬──────────────────────────┘
                                       │ JS resolvers                  │ direct Lambda resolver
                                       ▼                               ▼
                             DynamoDB: routes table          Lambda (Python): reads the month's
                             (reference data, GSI by         flight records from S3, filters to the
                              carrier)                       route, calculates governed metrics
                                                                       │
                                                                       ▼
                                                     S3: ontime/month=YYYY-MM/flights.csv
```

**Why it's a semantic layer:** "on-time %" has exactly one governed definition, in
one place (`lambda/performance/calc.py`), returned with every answer in the
`definition` field. Dashboards and apps stop re-implementing it differently.

## What gets deployed

| Resource | Purpose |
|---|---|
| AppSync GraphQL API (API-key auth, 30-day key) | The semantic layer: schema in `graphql/schema.graphql` |
| DynamoDB table `<stack>-routes` + `byCarrier` index | 10 routes (carrier, cities, distance, block time, aircraft, frequency), seeded automatically on deploy |
| S3 bucket | ~4,300 flight records for Jul–Sep 2026, uploaded automatically on deploy |
| Lambda `PerformanceFn` (Python 3.13, arm64) | Calculates on-time %, cancellation %, average / median / p90 arrival delay |

Everything is created by `cdk deploy` and removed by `cdk destroy` (bucket objects
and the table are deleted too). At demo volumes the cost is a few cents or less.

## Metric definitions

With `thresholdMinutes = N` (default 15, allowed 1–180):

- **On time**: arrived less than N minutes after scheduled arrival. N = 15 matches the US DOT definition.
- **On-time %** = on-time flights ÷ all scheduled flights. Cancelled and diverted flights count as not on time.
- **Delay statistics** (average, median, nearest-rank p90) cover arrived flights only; early arrivals are negative.

## About the data

`data/ontime/` is **synthetic** data shaped like the US DOT BTS *Reporting Carrier
On-Time Performance* dataset (same column names). It is generated by
`scripts/generate_sample_data.py` (seeded and reproducible) with realistic patterns:
congested airports (LGA, ORD, JFK, SFO), summer thunderstorm days, delays that build
through the day, and carrier differences. Because the column names match BTS, you can
drop in real BTS extracts later as `data/ontime/month=YYYY-MM/flights.csv`.

## Prerequisites

- AWS account and credentials configured (`aws configure` or SSO), with permission to create the resources above
- Python 3.9+
- Node.js 18+ and the CDK CLI: `npm install -g aws-cdk`
- AWS CLI v2 (for checking stack outputs)

## Deploy

```bash
git clone https://github.com/mickemora/airline-ontime-semantic-layer.git
cd airline-ontime-semantic-layer

python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt

python -m unittest discover tests  # all tests should pass, including stack tests
cdk synth > /dev/null              # confirms the stack builds

cdk bootstrap                      # once per account/region
cdk deploy
```

`cdk deploy` prints the outputs: `GraphQLApiUrl`, `GraphQLApiKey`, `DataBucketName`,
`RoutesTableName`, and more.

## Try it

**With the explorer (recommended for demos):**

```bash
python scripts/explorer.py
```

This opens a local web page at http://127.0.0.1:8765 where you can:

- build a question with controls (route or whole network, month, on-time threshold, a 5/15/30-minute comparison) or pick one of the example queries, and edit the GraphQL freely
- watch the request travel through an architecture diagram that lights up only the services the query touches
- read a step-by-step explanation: the DynamoDB operation each resolver ran, how many times the Lambda was invoked and with which arguments, which S3 file it read, and the round-trip time
- see real measurements pulled from CloudWatch: Lambda durations, cold starts, and whether S3 was read or the warm cache was used
- inspect the answer, raw JSON, the exact HTTP request, and the actual resolver and Lambda code

The explorer runs only on your machine and keeps the API key server-side. It uses your
AWS credentials to read the stack outputs and the Lambda's CloudWatch logs. Stop it with Ctrl+C.

**From the terminal:**

```bash
python scripts/query.py                         # list the example queries
python scripts/query.py RouteWithPerformance    # DynamoDB + Lambda/S3 in one query
python scripts/query.py ThresholdComparison     # 5 / 15 / 30-minute definitions side by side
python scripts/query.py NetworkJuly             # every route's July performance
python scripts/query.py MissingMonth            # clear error for a month with no data
```

**From the AWS console:** AppSync → `airline-ontime-semantic-layer` → **Queries**,
then paste queries from `queries/examples.graphql`.

## Tear down

cdk destroy

## Project layout

```
app.py                              CDK app entry point
airline_semantic_layer/stack.py     the stack (S3, DynamoDB, Lambda, AppSync)
graphql/schema.graphql              the semantic layer contract
resolvers/                          AppSync JS resolvers for DynamoDB
lambda/performance/                 handler.py (S3 + AppSync glue), calc.py (metric logic)
data/routes.json                    route reference data (seeded into DynamoDB)
data/ontime/                        flight records (uploaded to S3)
scripts/generate_sample_data.py     regenerates data/ontime
scripts/query.py                    runs example queries against the deployed API
scripts/explorer.py                 local web explorer server (UI + AppSync proxy + Lambda logs)
ui/index.html                       the explorer UI
tests/                              unit tests (calc, handler, data) and CDK assertions
```
